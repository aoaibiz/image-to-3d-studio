# Local CPU inference

From the project root, install uv from https://docs.astral.sh/uv/getting-started/installation/, then run `powershell -ExecutionPolicy Bypass -File engine/setup.ps1`. The setup installs Python 3.11.15 and dependencies into `.runtime/venv`, checks out TripoSR commit `107cefdc244c39106fa830359024f6a2f1c78871`, and downloads the official weights. The model file SHA-256 is checked against the official model repository metadata. Downloads are free; allow several gigabytes of disk space.

Run `.runtime\venv\Scripts\python.exe -u engine\infer.py INPUT.png OUTPUT_DIRECTORY --resolution 64 --texture-size 512`. Transparent inputs are cropped and centered automatically. For ordinary opaque photographs, rembg uses the U2Net weights provisioned by setup to remove the background locally; `--no-remove-bg` disables that for already framed inputs. Model weights and public configuration are downloaded; input images are not uploaded. Run one job at a time. 64 is the lower-memory default; 96 and 128 trade memory and time for detail.

The default path runs TripoSR on the selected foreground and retains the neural mesh and a checkpoint in the job's raw-export directory. For measurable layered desserts, frontal standing figures or side-view toy cars, it subsequently fits a new mesh to measured features of that same foreground and infers hidden surfaces. The profile and measurements are recorded in settings.json. A user-supplied recipe, a saved figurine, and a per-image model choice are unnecessary. Other subjects take the class-independent image-guided route. It measures frontal silhouette registration, protects sharp edges and disconnected components, and retains the unmodified inference when registration or mesh evidence is insufficient. Generic finishing and category-specific fitting both record their decision in settings.json. Examine results before judging fidelity.

For a finished job, model.glb and the self-contained editable.gltf carry the full scene and its materials. To use editable.obj, keep material.mtl and every material_N.png together with it. For a fitted scene, editable.ply stores a vertex-color approximation, and texture.png is a representative material image. input-processed.png records the input seen by TripoSR. The settings record baseline and finished output statistics, input and artifact hashes, timings, landmark selection and measured/inferred details. The displayed coordinate system is Y-up, +Z facing the input view. Units are relative. A generated figure may consist of several interlocking parts.

An earlier neural-only product demo on this Windows machine at resolution 64 produced a 7,248-face mesh in 83.63 seconds measured after Python imports; peak working set observed approximately 3.76 GiB. This is one sample, not a general performance or quality guarantee. Texture quality, unseen surfaces and printing suitability require human inspection. The UV-split GLB may be reported non-watertight by tools that treat seam vertices as disconnected; check `editable.ply` for topology.

Existing jobs exported before the normals/material fix can be corrected without rerunning inference: `.runtime\venv\Scripts\python.exe engine\repair_export.py JOB_DIRECTORY`. The first pre-repair export is retained in `original-export/`, and settings record the old and new GLB hashes. The repair requires the matching `editable.ply`, `model.glb`, and `texture.png`.

The full Windows bootstrap is `powershell -ExecutionPolicy Bypass -File setup.ps1` from the project root. It installs the CPU engine, viewer and clients, and the pinned Khronos Windows validator. Optional `-CachedWeights C:\path\to\model.ckpt` copies an existing official checkpoint only after its SHA-256 matches; the copied file is checked again. Python, dependency caches, validator and optional rembg U2Net cache are stored under `.runtime/`. The validator ZIP was obtained from Khronos GitHub release asset 200903724; GitHub API reports size 2,320,898 bytes and no published digest. Its ZIP SHA-256 (`c5068f51205deedc28acc3529ee7e11ee60e853454f673093398eba80142202c`) was measured from that download and is pinned, rather than represented as an independently published checksum.

Current inference saves the raw mesh and material under raw-export/<attempt-id>/. With a usable foreground alpha, it estimates a projection from the observed side and checks silhouette overlap before blending reference colors into visible texels. Occluded and back-facing surfaces retain inferred colors. The settings file records whether projection ran, the input and output hashes, and any reason for skipping. A visual review is still required. A semantic front may differ from the +Z direction of the input-facing camera.
